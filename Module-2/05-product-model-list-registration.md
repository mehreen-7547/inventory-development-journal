### Step 270: Define the Product model and create its database table
**Before this step:** Suppliers existed but products had nowhere to be stored.

**What we did and why:** A unique SKU identifies each item, while the supplier foreign key connects it to its supplier. PROTECT prevents deletion of a supplier referenced by products. DecimalField stores money without binary floating-point rounding. on_hand is not editable from an ordinary form, because later inventory transactions must control it.

**Filename: `catalog/models.py`**
```python
class Product(models.Model):
    sku = models.CharField(max_length=50, unique=True)
    name = models.CharField(max_length=150)
    category = models.CharField(max_length=100)
    supplier = models.ForeignKey(Supplier, on_delete=models.PROTECT)
    unit_price = models.DecimalField(max_digits=10, decimal_places=2)
    lead_time_days = models.PositiveIntegerField(default=0)
    safety_stock = models.PositiveIntegerField(default=0)
    on_hand = models.PositiveIntegerField(default=0, editable=False)
    is_active = models.BooleanField(default=True)

    def __str__(self):
        return self.name
```

### Step 271: Show the product list to Manager and Sales Staff
**Before this step:** Product records could exist, but staff had no catalogue page.

**What we did and why:** The view loads products with their suppliers in one related-object query. Both Manager and Sales can read the catalogue, while the Admin account is excluded by the role decorator. The template shows SKU, name, category, supplier, price, lead time, safety stock, on-hand quantity and active status.

**Filename: `catalog/views.py`**
```python
@login_required
@role_required('manager', 'sales')
def product_list(request):
    products = Product.objects.select_related('supplier').all().order_by('name')
    return render(request, 'catalog/product_list.html', {
        'products': products,
        'edit_mode': (
            request.user.role == 'manager'
            and request.GET.get('mode') == 'edit'
        )
    })
```
**Filename: `catalog/urls.py`**
```python
path('products/', views.product_list, name='product_list'),
```
**Filename: `catalog/templates/catalog/product_list.html`**

### Step 272: Register products through a Manager-only form
**Before this step:** Staff could see the catalogue but could not add a product from the website.

**What we did and why:** ModelForm lists allowed fields explicitly, so stock quantity and active status cannot be changed through this registration form. Only active suppliers are offered when creating a product. The view validates POST data, saves a valid product and returns to the list; invalid submissions redisplay errors.

**Filename: `catalog/forms.py`**
```python
class ProductForm(forms.ModelForm):
    class Meta:
        model = Product
        fields = [
            'sku', 'name', 'category', 'supplier',
            'unit_price', 'lead_time_days', 'safety_stock'
        ]
```
**Filename: `catalog/views.py`**
```python
@login_required
@role_required('manager')
def product_create(request):
    if request.method == 'POST':
        form = ProductForm(request.POST)
        if form.is_valid():
            form.save()
            return redirect('product_list')
    else:
        form = ProductForm()
    return render(request, 'catalog/product_form.html', {'form': form})
```
**Filename: `catalog/urls.py`**
```python
path('products/add/', views.product_create, name='product_create'),
```
