# How to study the project

Open the chapter that covers the feature you want to understand. Begin with **Before we begin**, **What we worked on**, and **Picture it this way**. These sections explain what was already possible and why we needed the next change.

For each step, read **Before this step** and **What we did and why** before reading its code. The walkthrough follows the code blocks in order. When a technical term is unfamiliar, use the [glossary](GLOSSARY.md).

Read **How we checked it** carefully. An untested feature was not treated as verified. Early Git commands, password settings, database resets, and email commands are part of the development history; do not rerun them merely to study.

After each chapter, explain the feature aloud: what existed first, what we changed, what happens when someone uses it, and how we tested it.
